# IdealDownward

IdealDownward decides the solvability of classical planning tasks with computer algebra, by
reducing them to ideal membership problems in polynomial rings. It uses the translator of the
[Fast Downward](https://www.fast-downward.org) planning system, whose search component has been
removed.


## How it works

1. Fast Downward's translator grounds the PDDL task into a SAS+ task (`output.sas`).
2. `src/ideal/stnf.py` transforms the task into simple transition normal form (STNF), in which
   every operator mentions the same variables in its precondition and in its effect
   (`output.sas_stnf`). By default, it skips operator copies whose precondition contains two
   facts of a mutex group, because such copies are applicable only in unreachable states.
3. `src/ideal/sas2singular.py` encodes every state as a monomial with one variable per fact and
   every operator as the binomial x^pre - x^eff. It writes a [Singular](https://www.singular.uni-kl.de)
   script (`output.sing`) that decides whether the monomial of the initial state lies in the ideal
   generated by the operator binomials and the goal monomial.
4. Singular answers the membership question with a Groebner basis (`output.singular_out`).
   - If the answer is no, the task is unsolvable. This holds for every task.
   - If the answer is yes, the initial state is connected to a goal state when operators may also
     be applied backwards. The planner then extracts a path from the membership certificate
     computed by Singular's `lift`, replaces backward steps by forward steps, and checks the
     resulting plan by simulation. This succeeds for every reversible task.


## Requirements

- Python 3.9 or newer
- Singular, for example from your package manager (`sudo apt install singular`) or from
  conda-forge (`conda install -c conda-forge singular`)


## Usage

    ./ideal-downward.py domain.pddl problem.pddl
    ./ideal-downward.py output.sas

Options:

- `--singular PATH`: Singular executable (default: `$SINGULAR`, otherwise `Singular`)
- `--workdir DIR`: directory for the intermediate files (default: current directory)
- `--plan-file FILE`: where to write the plan (default: `sas_plan`)
- `--max-operators N`: maximum number of operators after the STNF transformation
- `--no-mutexes`: keep the operator copies that violate mutexes
- `--search-limit N`: maximum number of states per search when a backward step cannot be replaced
  by a single operator

The three steps can also be run separately:

    python3 src/ideal/stnf.py output.sas output.sas_stnf
    python3 src/ideal/sas2singular.py output.sas_stnf output.sing
    Singular -q output.sing

To check whether a task is invertible, that is, whether every STNF operator is undone by a single
operator, run

    python3 src/ideal/invertibility.py output.sas

Invertible tasks are reversible, so for them the answer of the planner is exact.

Exit codes:

| Code | Meaning |
| ---- | ------- |
| 0    | plan found and validated |
| 11   | unsolvability proved |
| 12   | the initial state is connected to a goal state, but no plan was found (the task is not reversible) |
| 1    | error, for example an unsupported task |


## Limitations

- Axioms and conditional effects are not supported.
- Plans are not optimal.
- The STNF transformation is exponential in the number of variables that an operator changes
  without a precondition on them.
- For tasks that are not reversible, only negative answers are conclusive.
